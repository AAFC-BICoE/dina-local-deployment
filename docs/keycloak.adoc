= Keycloak

== Dev User

This option will allow the APIs to start without Keycloak but still function with a dev user.

The `keycloak/docker-compose.enable-dev-user.yml` config needs to be enabled inside of the
`start_stop_dina.sh`:

```sh
DINA_CONFIGS+=('keycloak/docker-compose.enable-dev-user.yml')
```

For the UI to work without keycloak, you need to be using UI dev mode, which can be enabled by
uncommenting the following line inside `start_stop_dina.sh`:

```sh
DINA_CONFIGS+=('docker-compose.dev.yml')
```

Inside of the `docker-compose.enable-dev-user.yml` file it can be configured which containers
the settings are applied, by default it is applied to all.

The dina-ui container expects a comma-separated list of the group and roles.

For example:

```
/aafc/user, /bicoe/read-only
```

Then each of the API's that you wish to use also need to be configured with the same group roles:

```json
"groupRole": {
  "aafc": ["user"],
  "bicoe": ["read-only"]
}
```

== Reset Users and Groups

Keycloak only imports `keycloak/keycloak-dina-starter-realm.json` when its database (`keycloak-data`) is empty,
so changes to that file (e.g. new or renamed users) are not picked up by an existing setup.
A reset deletes Keycloak's database, including any users added through the Keycloak admin console.

Uncomment the following line inside `start_stop_dina.sh`, then start the stack:

```sh
RESET_KEYCLOAK=true
```

```sh
./start_stop_dina.sh up -d
```

The reset only runs on `up`. Comment the line out again afterwards, otherwise every `up` resets Keycloak.

The reset script can also be run on its own before starting the stack:

```sh
./keycloak/reset-keycloak.sh
./start_stop_dina.sh up -d
```

To confirm the import, check the Keycloak logs:

```sh
./start_stop_dina.sh logs keycloak | grep "Realm 'dina'"
```

`Realm 'dina' imported` means the users were imported. `Realm 'dina' already exists. Import skipped` means
Keycloak's database was not reset.

The reset doesn't change `.env`. If the default super-user changed, also update `DINA_HTTP_DEFAULT_SU_USERNAME`
and `DINA_HTTP_DEFAULT_SU_PASSWORD` there.

== Settings

Traefik is responsible for TLS termination so Keycloak is configured with `KC_PROXY: edge`.

Keycloak Admin console is available at `https://keycloak.dina.local/auth`.

The main reason for having the admin console on a different hostname is to simplify the rules for not exposing it.
